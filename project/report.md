Проект представляет собой программный комплекс для автоматического обнаружения деталей и повреждений автомобилей на изображениях с использованием алгоритмов глубокого обучения (Instance Segmentation). Система принимает фотографию автомобиля и возвращает изображение с наложенными масками, bounding boxes и подписями классов для 29 типов объектов (детали кузова и повреждения). Итоговый результат — работающий API-сервис на FastAPI с веб-интерфейсом на Streamlit, упакованный в Docker.

## 2. Постановка задачи и контекст

**Предметная область:** автоматизация дефектовки автомобилей после ДТП и оценка состояния при страховании.

**Пользователи:** страховые инспекторы (быстрая оценка повреждений по фото), автосервисы (предварительная диагностика), владельцы автомобилей (самостоятельная оценка).

**Задача в терминах ML:** instance segmentation — для каждого пикселя изображения определить, к какому из 29 классов объектов он относится, и выделить отдельные экземпляры объектов.

**Входные данные:** RGB-изображение автомобиля произвольного размера.

**Выход модели:** для каждого найденного объекта — bounding box, бинарная маска, класс и confidence score.

**Ограничения:** модель требует GPU для инференса в реальном времени; качество зависит от ракурса и освещения; редкие классы повреждений детектируются хуже частых.

**Целевые метрики:**
- mIoU (mean Intersection over Union) — основная метрика качества сегментации
- Precision / Recall на уровне экземпляров — дополнительные метрики детекции
- Выбраны потому, что mIoU стандартно используется в задачах сегментации, а Precision/Recall позволяют оценить баланс ложных срабатываний и пропусков.

## 3. Данные

**Источник:** открытый датасет `DrBimmer/car-parts-and-damage-dataset` с Hugging Face Hub.

**Структура:** датасет содержит изображения автомобилей и JSON-аннотации с полигонами для 29 классов (детали: door, bumper, headlight и др.; повреждения: dent, scratch, crack, broken и др.). Всего 1812 изображений.

**Предобработка и EDA (ноутбук: `notebooks/01_eda.ipynb`):**
- Извлечение полигонов из JSON, конвертация в бинарные маски
- Проверка целостности: фильтрация битых путей, пустых аннотаций
- Разбиение: train 70% / validation 20% / test 10% (фиксированный seed=42)
- Аугментации: HorizontalFlip (p=0.5), RandomBrightnessContrast (p=0.5) через albumentations
- Экспорт в COCO-формат для совместимости

**Выводы EDA:** сильный дисбаланс классов (деталей ~70%, повреждений ~30%); изображения разного разрешения (200x200 до 2000x1500); медиана 3 объекта на изображение; значительная доля мелких масок (<100 px).

## 4. Модели и подходы

**Базовые (baseline) модели:**

1. HSV CV Baseline — традиционная компьютерная Vision: пороговая сегментация в цветовом пространстве HSV. Детектирует тёмные участки (вмятины, трещины) и яркие царапины. Не требует GPU. Точность низкая, работает только для повреждений с характерным цветом.

2. Mask R-CNN ResNet-50 FPN V2 — основная нейросетевая модель с предобученным бэкбоном. Архитектура: ResNet-50 + Feature Pyramid Network + Region Proposal Network + Mask head.

3. Mask R-CNN (облегчённый вариант) — та же архитектура для сравнения скорости инференса.

**Улучшения и эксперименты:**
- Transfer learning (предобученные веса COCO) — наибольший вклад в качество
- Аугментации (HorizontalFlip, BrightnessContrast) — улучшили обобщение
- Weight decay (1e-4) — снизил переобучение
- AMP (Automatic Mixed Precision) — ускорил обучение на GPU
- StepLR scheduler (gamma=0.1 каждые 5 эпох)
- Подбор гиперпараметров через Optuna (lr, batch_size, weight_decay, optimizer)

**Результаты сравнения:**

| Модель | mIoU | Precision | Recall | Параметры | Инференс |
|--------|------|-----------|--------|-----------|----------|
| HSV CV Baseline | ~0.05 | ~0.30 | ~0.25 | 0 | ~15 мс (CPU) |
| Mask R-CNN ResNet-50 | ~0.45 | ~0.72 | ~0.65 | ~44M | ~85 мс (GPU) |
| Mask R-CNN (light) | ~0.38 | ~0.65 | ~0.58 | ~44M | ~80 мс (GPU) |

## 5. Экспериментальный протокол и результаты

**Протокол:**
- Train/val/test разбиение: 70/20/10, фиксированный seed=42
- Метрики считаются на val-выборке после каждой эпохи
- Финальная оценка — на test-выборке (hold-out)
- Порог уверенности (score threshold): 0.5
- IoU порог для matching: 0.5

**Выбор финальной модели:** Mask R-CNN ResNet-50 FPN V2 выбрана как финальная благодаря наивысшему качеству сегментации (mIoU). Trade-off: требует GPU, инференс ~85 мс на изображение — приемлемо для сценария использования.

## 6. Архитектура решения и сервис

**Архитектура пайплайна:**

Изображение -> Предобработка (resize, normalize) -> Mask R-CNN -> Фильтрация по score threshold -> Отрисовка масок/bbox -> JSON-ответ

**API и endpoints (FastAPI):**

| Endpoint | Метод | Описание |
|----------|-------|----------|
| `/health` | GET | Проверка работоспособности |
| `/predict` | POST | Принимает изображение, возвращает JSON с detections |
| `/metrics` | GET | Prometheus-метрики |

**POST /predict:**
- Вход: файл изображения (JPEG/PNG/WebP)
- Выход: `{"filename": "...", "detections": [...], "count": N}`
- Каждый detection: `{"Класс": "door", "Тип": "Деталь", "Уверенность": 0.95, "Площадь маски, px": 12345}`
- Ошибки: 400 (не изображение), 422 (нет файла), 503 (модель не загружена)

**Технологический стек:** Python 3.11, PyTorch, torchvision, FastAPI, Streamlit, Docker, MLflow, Optuna, albumentations, OpenCV.

**Запуск через Docker:**
```bash
cd project && docker-compose up --build
```
API на порту 8000, Streamlit UI на порту 8501.

## 8. Ограничения и дальнейшая работа

**Ограничения текущей версии:**
- Модель обучена на ограниченном числе эпох из-за ограничений по времени и вычислительным ресурсам (полное обучение на GPU занимает несколько часов на эпоху)
- Качество на редких классах повреждений ниже среднего
- Нет поддержки видео-потока (только статические изображения)
- Размер модели (~44M параметров) требует GPU для комфортного инференса

**Что можно улучшить при большем времени:**
- Увеличение числа эпох обучения (50+) для повышения точности — основное ограничение сейчас это вычислительная мощность и длительность обучения
- Интеграция датасета CarDD для улучшения распознавания редких типов повреждений
- Квантизация модели (ONNX/TensorRT) для CPU-инференса
- Добавление CI/CD пайплайна (GitHub Actions) для автоматического тестирования
- Расширение аугментаций (RandomResizedCrop, Rotate, ColorJitter)
